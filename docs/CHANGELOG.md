## [1.1.0] - 2026-08-06

### 追加
- 起動時に監視元ディレクトリに既に存在するファイルを処理する機能（`FileRenameHandler.process_existing_files`）
- 監視元ディレクトリを `[Watch1]`, `[Watch2]`... と複数指定できる機能（単一の`Observer`にまとめて登録）
- 監視元ごとに独立した振り分けルール（`target_dirN` / `filenameN` / `patternN` / `regexN`）を設定できる機能
- 起動時に移動先が監視元と同一ディレクトリの場合（無限ループになる）エラー終了するチェック
- 移動先ディレクトリを `target_dir1`, `target_dir2`... と複数指定できる機能
- 移動先ごとに移動対象のファイル名を指定する `filename1`, `filename2`... を追加（カンマ区切りで複数指定可、空欄の場合は全ファイルが対象）
- ファイル名の正規表現による振り分けルール（`regex1`, `regex2`...）を追加し、完全一致に加えてパターンマッチに対応
- 移動先ごとにリネームパターンを切り替える機能（`pattern1`, `pattern2`... が `target_dirN` に対応）
- config_manager および tray_app の単体テスト

### 変更
- **破壊的変更**: `[Paths]` と `[Rename]` を廃止し、監視元ごとの `[WatchN]` セクションに統合
- **破壊的変更**: `[Paths]` の `target_dir` を廃止し、番号付きの `target_dir1` 以降に統一
- **破壊的変更**: `patternN` の意味を「複数のリネームパターン」から「`target_dirN` ごとのリネームパターン」に変更
- パターンが空欄の場合はファイル名に何も追加せずに移動するよう変更
- ファイル名の一致判定は拡張子込みの完全一致・大文字小文字を区別しない
- 存在しない監視元は除外して起動し、全ての監視元が存在しない場合のみ終了するよう変更
- トレイメニューの「監視フォルダを開く」を監視元ごとのサブメニューに変更
- `FileRenameHandler` は設定を読まず、移動先ルールと待機時間をコンストラクタで受け取るよう変更
- エラーハンドリングを強化し、`FileNotFoundError` に加えて `ValueError` も捕捉するよう変更

### 修正
- 移動先が1つも設定されていない場合にエラーログを出力して監視を開始しないよう修正

## [1.0.0] - 2025-12-23

- Windows トレイアプリケーションの基本機能を実装

- 複数のリネームパターンに対応した設定ファイル機能
